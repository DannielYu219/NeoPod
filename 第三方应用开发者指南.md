# NeoPod 第三方应用开发者指南

## 概述

NeoPod 支持通过 HTML/CSS/JavaScript 开发第三方插件应用。这些应用可以在 NeoPod 的 Dev 页面中运行，提供丰富的交互功能。

## 文件结构

### 应用存放位置
- HTML 插件应用应放置在应用的 `Documents/dev/` 文件夹中
- 支持的文件格式：`.html` 和 `.htm`
- 应用会自动按文件名排序显示在 Dev 页面列表中

### 文件命名规范
- 使用英文或拼音命名，避免使用特殊字符
- 文件名应简洁明了，能够描述应用功能
- 例如：`calculator.html`、`todo_list.html`、`test_plugin.html`

## 开发规范

### HTML 文件结构要求

每个 HTML 文件开头必须包含以下注释：

```html
<!--
文件作用：[描述此文件的主要功能]
依赖：[列出所需的外部依赖，如无则写"无"]
输入：[描述用户输入方式，如按钮点击、文本输入等]
输出：[描述应用输出内容，如数据显示、界面更新等]
实现方式：[简要说明核心实现逻辑]
-->
```

**示例：**
```html
<!--
文件作用：计数器应用，支持增加、减少和重置计数
依赖：无（纯原生JavaScript）
输入：用户点击按钮进行操作
输出：实时显示当前计数值
实现方式：使用JavaScript变量存储计数值，通过DOM操作更新显示
-->
```

## WebView 兼容性

### 支持的技术栈
- **HTML5**：完整的 HTML5 支持
- **CSS3**：包括 Flexbox、Grid、动画等现代特性
- **JavaScript**：ES6+ 语法支持
- **API**：
  - LocalStorage（本地存储）
  - SessionStorage
  - Canvas API
  - Web Audio API
  - 等标准 Web API
  - **NeoPod 文件系统 API**（见下文）

### NeoPod 文件系统 API

NeoPod 提供了本地文件读写功能，允许插件应用访问 `Documents/dev/` 文件夹中的文件。

#### 可用 API

**同步读取文件**
```javascript
var content = NeoPod.readFileSync('dev/myfile.txt');
```

**写入文件（回调方式）**
```javascript
NeoPod.writeFile('dev/newfile.txt', 'Hello World!', 
    function() { console.log('File saved!'); }, 
    function(error) { console.error('Error saving:', error); }
);
```

**异步写入文件**
```javascript
try {
    await NeoPod.writeFileAsync('dev/updatedFile.txt', 'New Content');
} catch (error) {
    console.error('File write failed:', error);
}
```

**读取目录（回调方式）**
```javascript
NeoPod.readDir('dev/', function(error, files) {
    if (error) {
        console.error('Error reading dir:', error);
    } else {
        console.log('Files in dir:', files);
        // files 包含 {name, isDirectory, size, modified, extension}
    }
});
```

**同步读取目录**
```javascript
var files = await NeoPod.readDirSync('dev/');
console.log('Files:', files);
```

**删除文件**
```javascript
NeoPod.deleteFile('dev/todelete.txt', 
    function() { console.log('File deleted'); }, 
    function(error) { console.error('Error deleting:', error); }
);
```

#### 文件路径规范

- 所有文件路径都相对于 `Documents/` 目录
- `dev/` 文件夹是专门用于插件应用的
- 文件路径示例：`dev/myfile.txt`、`dev/data/config.json`
- 目录路径示例：`dev/`、`dev/subfolder/`

#### 文件信息对象

`readDir` 和 `readDirSync` 返回的文件对象包含以下属性：
- `name`：文件名
- `isDirectory`：是否为目录（布尔值）
- `size`：文件大小（字节）
- `modified`：最后修改时间（时间戳）
- `extension`：文件扩展名

#### 文件操作示例

**示例1：保存用户配置**
```javascript
function saveConfig(config) {
    NeoPod.writeFile('dev/config.json', JSON.stringify(config),
        function() {
            console.log('配置已保存');
        },
        function(error) {
            console.error('保存失败:', error);
        }
    );
}

function loadConfig() {
    try {
        var content = NeoPod.readFileSync('dev/config.json');
        return JSON.parse(content);
    } catch (error) {
        return { theme: 'dark', language: 'zh-CN' };
    }
}
```

**示例2：列出所有插件文件**
```javascript
NeoPod.readDir('dev/', function(error, files) {
    if (error) {
        console.error('读取目录失败:', error);
        return;
    }
    
    var htmlFiles = files.filter(function(file) {
        return file.extension === 'html' || file.extension === 'htm';
    });
    
    console.log('找到的HTML文件:', htmlFiles);
});
```

**示例3：异步保存日志**
```javascript
async function saveLog(message) {
    var timestamp = new Date().toISOString();
    var logEntry = '[' + timestamp + '] ' + message + '\n';
    
    try {
        await NeoPod.writeFileAsync('dev/logs/app.log', logEntry);
        console.log('日志已保存');
    } catch (error) {
        console.error('日志保存失败:', error);
    }
}
```

### 不支持的功能
- 网络请求（需特殊配置）
- 原生插件
- WebGL（部分支持）

## 设计规范

### Metro 设计语言

NeoPod 采用类似 Windows Phone 7 和 Zune HD 的 Metro 设计语言，强调内容优先、动态交互和流畅动画。

#### 核心设计原则

1. **内容优先**
   - 减少装饰元素，突出核心内容
   - 使用大字体和清晰的排版
   - 信息层次分明，易于浏览

2. **动态交互**
   - 使用动画和过渡效果增强用户体验
   - 元素状态变化要有明确的视觉反馈
   - 支持触摸手势和流畅的页面切换

3. **扁平化设计**
   - 避免过度装饰和阴影
   - 使用纯色块和渐变
   - 强调功能而非视觉特效

4. **网格布局**
   - 采用对齐的网格系统
   - 元素间距统一
   - 视觉节奏一致

#### 视觉风格
NeoPod 采用深色主题设计，建议应用遵循以下设计规范：

##### 配色方案
- **主色调**：`#f57309`（橙色）
- **背景色**：`#1a1a2e` 到 `#16213e` 渐变
- **文字色**：`#ffffff`（白色）
- **次要文字色**：`rgba(255, 255, 255, 0.6)`
- **卡片背景**：`rgba(255, 255, 255, 0.05)`
- **导航栏背景**：`rgba(0, 0, 0, 0.3)`

##### 字体规范
```css
font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
```

**字体大小参考：**
- 标题：18-20px（中等粗细）
- 大标题：32-72px（细体）
- 正文：14-16px
- 标签：11-12px（大写，字间距 0.5-1px）

##### 组件样式

**卡片**
- 圆角：16px
- 背景：半透明 `rgba(255, 255, 255, 0.05)`
- 模糊效果：`backdrop-filter: blur(10px)`
- 边框：`1px solid rgba(255, 255, 255, 0.1)`
- 间距：底部 16px

**按钮**
- 圆角：8-12px
- 背景：主色调
- 内边距：16px 40px
- 字体：18px，中等粗细
- 悬停效果：缩放 1.05 倍
- 点击效果：缩放 0.95 倍

**输入框**
- 圆角：8-12px
- 背景：半透明 `rgba(255, 255, 255, 0.05)`
- 边框：`1px solid rgba(255, 255, 255, 0.1)`
- 内边距：16px 20px
- 聚焦时：边框颜色变为主色调

**导航栏**
- 顶部栏：高度自适应，背景半透明
- 底部导航：固定在底部，水平排列
- 导航项：图标 + 文字，垂直排列
- 激活状态：主色调高亮

##### 图标使用
- 优先使用 Emoji 图标（简单、直观）
- 图标大小：24px（导航）、48px（空状态）
- 保持风格统一

##### 布局结构

```css
    /* 顶部导航栏 */

    /* 底部导航栏 */

```

### 响应式设计
应用应适配不同屏幕尺寸：
- 使用相对单位（rem, em, %）
- 避免固定宽高
- 使用 Flexbox 或 Grid 布局
- 触摸区域至少 44x44px
- 支持横竖屏切换

## 交互设计

### Metro 风格交互

#### 页面切换
- 使用底部导航切换主要功能模块
- 页面切换使用滑动动画（translateX）
- 保持当前页面状态，避免重复加载

#### 触摸反馈
```css
.btn:active {
    transform: scale(0.95);
}

.card:hover {
    transform: translateY(-2px);
}

.nav-item:active {
    transform: scale(0.95);
}
```

#### 动画效果
```css
transition: all 0.3s ease;
```

#### 动态效果
- 计数器数值变化时使用脉冲动画
- 页面切换使用平滑过渡
- 列表项删除使用淡出效果

### 加载状态
提供清晰的加载反馈，避免用户等待时产生困惑。

## 性能优化

### 资源管理
- 避免使用大型图片，使用 SVG 或 CSS 绘图
- 压缩 CSS 和 JavaScript
- 使用事件委托减少事件监听器数量

### 内存管理
- 及时清理不再使用的 DOM 元素
- 避免内存泄漏（如未移除的事件监听器）
- 使用防抖和节流优化高频事件

### 渲染优化
- 使用 CSS transform 和 opacity 进行动画
- 避免频繁的 DOM 操作
- 使用文档片段批量更新

### 文件操作优化
- 避免频繁的小文件读写操作
- 使用批量操作减少 I/O 次数
- 合理使用同步和异步 API

```html
        function render() {
            const list = document.getElementById('todoList');
            list.innerHTML = todos.map((todo, i) => `
                <li class="todo-item">
                    <div class="todo-checkbox ${todo.done ? 'checked' : ''}" onclick="toggle(${i})"></div>
                    <span class="todo-text ${todo.done ? 'completed' : ''}">${todo.text}</span>
                    <span class="todo-delete" onclick="remove(${i})">×</span>
                </li>
            `).join('');
        }
        
        function add() {
            const input = document.getElementById('todoInput');
            const text = input.value.trim();
            if (text) {
                todos.push({ text: text, done: false });
                input.value = '';
                save();
            }
        }
        
        function toggle(i) {
            todos[i].done = !todos[i].done;
            save();
        }
        
        function remove(i) {
            todos.splice(i, 1);
            save();
        }
        
        function save() {
            localStorage.setItem('todos', JSON.stringify(todos));
            render();
        }
        
        document.getElementById('todoInput').addEventListener('keypress', e => {
            if (e.key === 'Enter') add();
        });
        
        render();
    </script>
</body>
</html>
```

## 最佳实践

### 1. 代码组织
- 将 CSS、HTML 和 JavaScript 分离到不同区域
- 使用有意义的变量和函数名
- 添加必要的注释

### 2. 用户体验
- 提供清晰的视觉反馈
- 避免使用 alert()，使用自定义提示
- 支持键盘操作（如 Enter 提交）

### 3. 错误处理
- 验证用户输入
- 提供友好的错误提示
- 记录错误日志便于调试

### 4. 性能考虑
- 避免频繁的 DOM 操作
- 使用文档片段批量更新
- 合理使用缓存
- 使用 CSS transform 进行动画
- 优化文件操作频率

- 使用底部导航切换功能模块
- 页面切换使用滑动动画
- 元素状态变化有明确反馈
- 保持视觉节奏一致

- 合理使用同步和异步 API

## 常见问题

### Q: 如何访问本地存储？
A: 使用 `localStorage` API，数据会持久化保存。

### Q: 如何读写文件？
A: 使用 `NeoPod.readFileSync()`、`NeoPod.writeFile()` 等 API，详见"NeoPod 文件系统 API"章节。

### Q: 支持网络请求吗？
A: 默认不支持，如需网络功能请联系 NeoPod 团队。

### Q: 如何与其他应用交互？
A: 目前应用间相互独立，未来版本可能支持应用间通信。

### Q: 文件大小有限制吗？
A: 建议单个 HTML 文件不超过 1MB。

### Q: 支持哪些 JavaScript 框架？
A: 可以使用 Vue.js、React 等框架，但建议使用原生 JavaScript 以获得最佳性能。

### Q: 如何实现 Metro 风格的页面切换？
A: 使用底部导航 + CSS transform 实现滑动切换效果，参考测试插件示例。

### Q: 如何适配 iOS 安全区域？
A: 使用 `viewport-fit=cover` 和 CSS 环境变量 `env(safe-area-inset-*)` 进行适配。

### Q: 文件操作支持哪些路径？
A: 支持相对于 `Documents/` 目录的路径，推荐使用 `dev/` 文件夹存储应用数据。

### Q: 如何处理文件操作错误？
A: 所有文件操作 API 都提供了错误处理回调，建议始终处理错误情况。
